# Semantic Change Understanding & Change-VQA Architecture

This document details the bi-temporal change detection and reasoning pipeline implemented in `ml_backend/semantic_change.py` and wrapped by `ChangeVQATool` in `ml_backend/tools.py`.

---

## 1. Architectural Overview

NexSpace upgrades bi-temporal analysis beyond classical pixel-difference thresholding by establishing a multi-stage semantic reasoning pipeline:

```text
BEFORE IMAGE (T1)                     AFTER IMAGE (T2)
       │                                     │
       └──────────────────┬──────────────────┘
                          ▼
             1. VALIDATION & CO-REGISTRATION
             • Dimensions, CRS, Affine, Overlap
                          ▼
             2. TEMPORAL FEATURE EXTRACTION
             • RSICD Contrastive Embeddings
             • Zero-Shot Object Grounding (T1 & T2)
             • Multi-Scale Difference Map (ΔPixel)
                          ▼
             3. ANOMALY CLUSTERING & BOX EXTRACTION
             • Morphological filtering, Connected Components
             • Bounding Box extraction in canonical [xmin,ymin,xmax,ymax]
                          ▼
             4. SEMANTIC CATEGORIZATION
             • Pixel Change vs. Object Change vs. Semantic Change
                          ▼
             5. CHANGE-VQA REASONING
             • Targeted Natural Language Query Resolution
             • Spatial Association ("near the buildings")
                          ▼
             6. MODEL PROVENANCE & CALIBRATED EVIDENCE
```

---

## 2. Distinction of Change Tiers

NexSpace strictly separates change into three distinct tiers:

1. **PIXEL CHANGE:**
   - Raw photometric or radiometric variance (spectral shift, illumination differences, seasonal vegetation changes, sensor noise).
   - *Example:* "Surface reflectivity variance across 14.2% of the scene."
   - *Model Assertion:* Heuristic / Classical Difference metric.

2. **OBJECT CHANGE:**
   - Structural appearance, disappearance, or morphological modification of discrete physical entities (buildings, roads, aircraft, ships).
   - *Example:* "2 new built structures detected in quadrant 3 (Bounding boxes [520, 110, 680, 290])."
   - *Model Assertion:* Verified via Grounding DINO object difference mapping.

3. **SEMANTIC CHANGE:**
   - High-level functional transition of land-use classification between $T_1$ and $T_2$.
   - *Example:* "Agricultural field transitioned into industrial/commercial development."
   - *Model Assertion:* Zero-shot RSICD multi-class transition distribution.

## 3. Change-VQA Query Resolution

When a user submits a natural-language query such as:
> *"What changed near the buildings?"*

The `RemoteSensingSemanticChangeEngine` executes:
1. **Target Identification:** Identifies candidate anchor objects ("buildings") in $T_1$ and $T_2$.
2. **Spatial Association:** Filters the bi-temporal change anomaly mask to regions overlapping or adjacent to the anchor bounding boxes.
3. **Semantic Interpretation:** Queries the RS feature extractor to classify the change in the localized ROI.
4. **Structured Response:**
   ```json
   {
     "answer": "Detected new construction activities adjacent to existing structures.",
     "before_interpretation": "Low-density residential structures with surrounding green vegetation.",
     "after_interpretation": "High-density built-up structures and cleared ground.",
     "what_changed": "Vegetation clearing and 2 new built structures.",
     "changed_regions": [[120, 340, 280, 510], [540, 110, 700, 310]],
     "change_type": "OBJECT CHANGE",
     "confidence": 0.84,
     "confidence_source": "uncalibrated_model",
     "model_id": "flax-community/clip-rsicd + grounding-dino-baseline",
     "status": "RESEARCH BASELINE"
   }
   ```

## 4. Grounding & Coordinate Standards

All bounding boxes generated by the change pipeline conform to:
- **Canonical Coordinates:** `[xmin, ymin, xmax, ymax]`
- **Normalized Scale:** `0` to `1000` integer coordinates for cross-resolution frontend alignment.
- **Inversion Prevention:** Guaranteed `xmin < xmax` and `ymin < ymax`.
